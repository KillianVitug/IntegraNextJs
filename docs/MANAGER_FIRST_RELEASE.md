## Approved scope and implemented behavior

- Leave filing uses one form: the visible employee and leave type are the submitted values. It retains entered values after errors and balance checks, confirms the saved Pending record, deduplicates identical pending retries and locks edits/cancellation to the request owner, current scope and Pending state. Both original and replacement employees must be authorized. Old native submission routes reject without a write and preserve escaped submitted entries for recovery. Browsing does not initialize leave policies.
- Manager attendance is read-only for this release. Seven legacy mutation actions and four native POST routes reject before business-data operations. Two exported Admin calendar-refresh helpers also authenticate and reject a spoofed actor. Original evidence/history is retained. Approved/Posted payroll protections and separate Admin workflows remain.
- The dashboard focuses on attendance findings and pending leave/schedule requests, shows the branch/period and source-observation time, and links directly to the selected employee/day. Attendance replaces the import/edit-heavy DTR screen. Calendar is a secondary planning link; Schedules remains available.
- `/managerProvisional` and `/api/manager/provisional` expose an explicit safe projection: time, schedules/breaks, effective/retained punches, static findings, source observation, leave coverage and review indicators. There are no pay amounts, rates, salaries, deductions, bank details, monetary formulas, unrestricted notes, raw diagnostics or financial filters. The API rechecks current manager scope and is private/no-store. Reads use a read-only repeatable-read transaction and do not call payroll computation.
- The default period is selected around today independently of future catalog entries. Recorded counts exclude today, future dates and an overnight shift before its scheduled end. Half-day leave requires remaining-attendance review. Legacy nullable leave dates use filing date; legacy type resolution stays in the read-only transaction.

## Boundaries

Current employee/branch membership determines visibility, including historical periods; historical manager membership is not inferred. A maximum source observation does not prove every phone synced or every identity matched. A missing record does not establish absence. Partial-day review is conservative and does not change the existing Admin payroll arithmetic or certify that arithmetic. Final financial review remains with Payroll Admin. Manager correction requests, selectable capabilities and Admin takeover are separate work.

No entitlement, rounding, leave allocation, balance ledger or overtime payment rule is changed. Read [PHILIPPINE_LABOR_COMPLIANCE.md](PHILIPPINE_LABOR_COMPLIANCE.md) before related changes. Primary sources reviewed 14 October 2026: [Omnibus Rules, Book III Rules I and V](https://lawphil.net/statutes/repacts/ra1989/omnibus_labor_1989.html), [Robina Farms v. Villa](https://lawphil.net/judjuris/juri2016/apr2016/gr_175869_2016.html), and the [Data Privacy Act](https://privacy.gov.ph/data-privacy-act-/). Distinguish statutory coverage, favorable company/CBA benefits, adopted policies and implemented calculations. Employment coverage, actual required/permitted work and leave entitlement are fact-specific; the UI does not decide them.
